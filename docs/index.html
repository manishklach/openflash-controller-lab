One problem, every layer.

A fast controller is not a fast flash chip. It is coordination: enough outstanding work to hide NAND latency, placement that preserves channel and die parallelism, queues that never lose ownership, and recovery that favors data honesty over optimistic replay.

Performance thesis

NAND latency is mostly hidden, not removed. The controller wins by keeping independent dies busy while guarding tail latency, write amplification, wear, ECC retries, and recovery correctness.

What is implemented today.

SIMULATOR + FTL

Deterministic channel/die timing, page mapping, GC, wear, ECC retry, trace replay, and reproducible scheduling experiments.

QUEUE TRANSPORT

64-byte little-endian descriptors, phase tags, coherent DMA rings, admin queue negotiation, queue-local doorbells, and MSI-X.

LINUX DATA PATH

An experimental /dev/openflash0 uses blk-mq, tag-owned completions, SGL DMA mapping, read/write/flush/discard, and timeout reset recovery.

Experimental boundary. QEMU media is RAM-backed. Linux FUA and durable flush guarantees are not implemented. Timed-out commands are failed, never replayed, because media execution cannot be proven. Do not store valuable data here.

The path to a controller.

Validated software transport

ABI v0.2, SGL DMA, QEMU controller, Linux blk-mq data path, and timeout-driven reset recovery.

Correctness and durability

FUA and durable flush semantics, command abort, fault injection, reset test images, telemetry, and fio verification.

Scale and measure

Per-CPU queues, interrupt groups, queue-depth scaling, CPU/request profiling, and latency gates under GC pressure.

Firmware and RTL

Persistent FTL metadata, ECC characterization, ONFI channel engines, power-loss testing, and an FPGA scheduler/testbench.
